# Auth Split Layout & Flutter Signup — Design

**Date:** 2026-07-30
**Scope:** Restyle every auth screen on both platforms to a 45/55 split with a branded teal panel,
and add the signup screen the Flutter app is missing.
**Repos:** `magnetrip-web` (Next.js) and `magnetrip` (Flutter). Both change; the shared design-token
pipeline lives in `magnetrip-web`.

## Goals

1. Auth screens use a 45% branded panel and a 55% white form column, instead of a centered card.
2. The app logo appears on the panel as a white-ringed circular medallion.
3. The panel colour is a deep teal gradient derived from the existing primary — no unrelated hue.
4. The Flutter app gains a signup screen with parity to web's, reachable from its login screen.
5. Client-side validation copy is identical across platforms.

Out of scope: any change to auth *logic* (sign-in, reset, callback handling), social login,
dark mode, deep-linking the email-confirmation link back into the Flutter app, and adding a
React component-test harness to the web repo.

## 1. Design tokens

Two colours extend the teal ramp in `design/tokens.json`:

```json
"primaryDark": "#0B6E66",
"primaryDeep": "#08544E",
```

`scripts/generate-tokens.mjs` holds **hardcoded emit lists**, so adding the keys to `tokens.json`
alone produces nothing. Three edits are required:

- `buildCss` → `root`: `--primary-dark`, `--primary-deep`.
- `buildCss` → `theme`: `--color-primary-dark: var(--primary-dark);` and the `primary-deep`
  equivalent, so Tailwind resolves `via-primary-dark` / `to-primary-deep`.
- `buildDart` → `colors`: `primaryDark`, `primaryDeep`.

`scripts/generate-tokens.test.mjs` extends to assert all of the above. `pnpm tokens` then
regenerates `app/tokens.generated.css` **and** `../magnetrip/lib/theme/app_theme.dart`. Neither
generated file is ever hand-edited.

## 2. Visual contract (shared by both platforms)

**Gradient.** 160°, `primary 0% → primaryDark 45% → primaryDeep 100%`.

**Geometry.**

| Context | Panel | Form column |
| --- | --- | --- |
| Web ≥ 768px (`md:`) | left, 45% width, full height | right, fills remainder |
| Web < 768px | top, `45svh` | below, fills remainder |
| Flutter (always) | top, 45% of screen height | below, fills remainder |

**Panel contents**, centered on both axes, in order:

1. Circular medallion — the logo, `cover`-fitted, 3px `rgba(255,255,255,0.95)` ring, soft drop
   shadow. 128px (web ≥768px) / 96px (web <768px) / 112dp (Flutter).
2. Wordmark "Magnetrip" — white, extrabold, tight tracking. 24px / 20px / 22sp.
3. Tagline "Tap a magnet. Relive the trip." — white at 90% opacity, ~13px. This is existing shipped copy
   from `app/layout.tsx` metadata, reused rather than newly invented.

**Form column.** White (`surface` token). Content capped at 384px wide, vertically centered. The
card wrapper, its border and its shadow are removed on web — the white column *is* the card now.

**Contrast.** White on `#0D9488` computes to **3.74:1**, which fails WCAG AA for body text. Placing
`primaryDark` at the 45% gradient stop puts the centered content block on ≈`#0B6E66`, giving
**6.15:1** for the wordmark and **≈5.3:1** for the 90%-opacity tagline. Both pass AA. This is the
reason the middle stop is at 45% and not further down. These are computed values; confirm with a
contrast checker during verification.

**Medallion accessibility.** Decorative on both platforms — `alt=""` on web, no semantic label in
Flutter. The wordmark immediately beside it already announces "Magnetrip"; labelling the image
would make screen readers say it twice.

## 3. Web implementation

| File | Change |
| --- | --- |
| `design/tokens.json` | add `primaryDark`, `primaryDeep` |
| `scripts/generate-tokens.mjs` | emit both in `buildCss` and `buildDart` |
| `scripts/generate-tokens.test.mjs` | extend assertions |
| `app/tokens.generated.css` | regenerated by `pnpm tokens` |
| `public/brand/logo.png` | **new** — `sips -Z 384 assets/logo.png --out public/brand/logo.png` |
| `components/auth/auth-brand-panel.tsx` | **new** |
| `components/auth/auth-shell.tsx` | rewrite internals; props unchanged |
| `app/(auth)/layout.tsx` | rewrite — owns the split geometry |

**Component boundaries.**

- `AuthBrandPanel` — no props. Renders gradient, medallion, wordmark, tagline. Only import is
  `next/image`. Knows nothing about forms or routing.
- `AuthShell` — props stay `{ title, subtitle?, children }`. Drops the `Card` wrapper and the text
  wordmark (which moves to the panel); keeps the heading block and form slot in a `max-w-sm` column.
- `app/(auth)/layout.tsx` — knows only the 45/55 ratio and the `md:` breakpoint.

Because `AuthShell`'s signature is unchanged, **no page files change.** All four routes — `login`,
`signup`, `forgot-password`, `reset-password` — inherit the new look through the shell.

**Layout shape.**

```tsx
<div className="flex min-h-svh flex-col md:flex-row">
  <AuthBrandPanel />   {/* h-[45svh] shrink-0 md:h-auto md:w-[45%] */}
  <main className="flex flex-1 items-center justify-center bg-card px-6 py-10">
    {children}
  </main>
</div>
```

Colours come from tokens only:
`bg-[linear-gradient(160deg,var(--primary)_0%,var(--primary-dark)_45%,var(--primary-deep)_100%)]`
and `bg-card`. Nothing hardcoded, per CLAUDE.md.

**Asset.** 384px covers a 128px medallion at 3× DPR and takes the 1.7 MB source down to roughly
100 KB. Rendered via `next/image` with `priority`, so it does not pop in after first paint.

## 4. Flutter restyle

**New shared widget** `lib/features/auth/auth_scaffold.dart`:

```dart
AuthScaffold({required String title, String? subtitle, required List<Widget> children})
```

It owns the band plus the form column, and is the Flutter counterpart to web's `AuthShell`. All
three auth screens render through it.

- Band height = `MediaQuery.sizeOf(context).height * 0.45`. Screen height is unaffected by the
  keyboard, so the band does not resize when a field gains focus.
- The page sits in a `SingleChildScrollView`. An open keyboard scrolls the band off-screen and
  Flutter auto-scrolls the focused field into view. No bespoke keyboard handling.
- The gradient runs edge-to-edge behind the status bar; panel content is inset by
  `MediaQuery.paddingOf(context).top`. Wrapped in `AnnotatedRegion<SystemUiOverlayStyle>` with
  `statusBarIconBrightness: Brightness.light` so status-bar icons stay legible on teal.
- Form column: 400px max width, `MagnetripSpacing.s6` padding, matching today's constraint. (Web
  caps at 384px; each platform keeps the width it already uses rather than forcing one number.)
- `title` and `subtitle` render at the top of the **form column**, not on the panel — the panel
  carries brand only. This matches web, where `AuthShell` owns the heading block.

**`forgot_password_screen.dart` loses its `AppBar`.** A back arrow floating on the teal band reads
as a mistake, and the screen already has a "Back to sign in" text button in its body — the same
pattern web uses. The AppBar goes; the text button stays.

**Assets.** `assets/brand/logo.png` (`sips -Z 384`; a 112dp medallion at 3× needs 336px), declared
in `pubspec.yaml`, whose `assets:` block is currently commented out. One 384px file — no `2.0x` /
`3.0x` variant directories.

**Screens updated:** `login_screen.dart` and `forgot_password_screen.dart` drop their inline
wordmark/heading scaffolding and pass `title` / `subtitle` / body to `AuthScaffold`.

## 5. Flutter signup

| File | Change |
| --- | --- |
| `lib/features/auth/auth_validation.dart` | **new** — pure validators |
| `lib/features/auth/signup_screen.dart` | **new** |
| `lib/features/auth/auth_providers.dart` | add `AuthController.signUp` |
| `lib/core/router.dart` | add `/signup` route **and** add it to `_authRoutes` |
| `lib/features/auth/login_screen.dart` | add "No account? Create one" link to `/signup` |

**Validation module.** Message strings are copied verbatim from web's
`lib/validation/auth.ts` so the platforms cannot drift:

```dart
String? validateEmail(String value);                       // 'Enter a valid email address'
String? validateLoginPassword(String value);               // 'Enter your password'   (min 1)
String? validateNewPassword(String value);                 // 'Password must be at least 8 characters'
String? validatePasswordConfirmation(String a, String b);  // 'Passwords do not match'
String? validateLoginForm({required String email, required String password});
String? validateSignupForm({required String email, required String password,
                            required String confirmPassword});
```

The two `*Form` helpers return the **first** error, mirroring how the web reads
`parsed.error.issues[0]`. The email pattern is deliberately simple —
`^[^@\s]+@[^@\s]+\.[^@\s]+$` — because the server remains the real authority.

`validateNewPassword` also enforces web's 72-character ceiling. This is the one message that is
*not* verbatim: web's `z.string().max(72)` carries no custom message and falls back to Zod's
default, so Flutter uses `'Password must be 72 characters or fewer'`. Reaching it requires typing
73 characters, so the divergence is not worth changing the web schema over.

**Consequence worth stating:** login currently only checks `isEmpty`. Routing it through
`validateLoginForm` makes it reject malformed emails client-side, matching web. That is a behaviour
change beyond a restyle, and it is intended.

**Controller.**

```dart
Future<bool> signUp({required String email, required String password}) async {
  final res = await _client.auth.signUp(
    email: email,
    password: password,
    emailRedirectTo: '${AppConfig.apiBaseUrl}/auth/callback?next=/dashboard',
  );
  return res.session != null;
}
```

Returning `bool` keeps `AuthResponse` out of the widget layer. `true` means email confirmation is
disabled and the router's redirect takes over, exactly as `signIn` behaves. `false` means the
screen shows its "Check your email" state.

**Screen.** Email, password, confirm-password fields; validates through `validateSignupForm` before
calling the controller; maps thrown errors with the existing `authErrorMessage`. Its
"Check your email" state and its copy mirror web's `signup/page.tsx`. `auth_error.dart` already maps
`user_already_exists` and `weak_password`, so error copy needs no change.

**Router trap.** `_authRoutes` gates the redirect in `redirectLocation`. Adding the `GoRoute`
without adding `/signup` to that set bounces every signed-out visitor straight back to `/login`.
Both edits belong in one commit.

**Known limitation, inherited not introduced.** `emailRedirectTo` points at the web callback, so a
phone user tapping the confirmation link lands on the *web* dashboard rather than back in the app.
`sendPasswordReset` already behaves this way. Deep-linking is out of scope.

## 6. Testing and verification

**Flutter** — TDD, following the repo's existing widget-test precedent (`mocktail` +
`ProviderScope(overrides:)`).

1. `test/features/auth/auth_validation_test.dart` — written first. Each validator plus both `*Form`
   helpers, asserting the exact web-parity strings and first-error ordering.
2. `test/core/router_test.dart` — extend both existing cases: `/signup` returns `null` when signed
   out and `/` when signed in.
3. `test/features/auth/signup_screen_test.dart` — via
   `class MockAuthController extends Mock implements AuthController {}`:
   mismatched passwords error *without* calling the controller; a short password is blocked;
   `signUp` returning `false` shows "Check your email"; a thrown
   `AuthException` with code `user_already_exists` surfaces the mapped copy; the submit button is
   disabled while loading.
4. `test/features/auth/login_screen_test.dart` — **new**, thin: the "Create one" link navigates to
   `/signup`.

Restyling the two existing screens is covered by `flutter analyze`, `flutter test` and a manual
run. Widget tests are not being backfilled for screens that never had them.

**Web** — Vitest runs `environment: 'node'` with no jsdom or Testing Library, so React component
tests are not possible, and adding that harness is not in scope for a login restyle. Instead:

- `pnpm test` — unit suite green, including the extended generator test.
- `pnpm lint` and `pnpm build` clean.
- `pnpm tokens` run twice produces no diff on the second run (generator is deterministic).
- Manual pass over all four auth routes at 1440px and 375px, with screenshots, plus a check that
  keyboard focus order is still email → password → submit.

## 7. Open items

- **Tagline copy** is "Tap a magnet. Relive the trip." (requester's choice, 2026-07-30).
  Swapping or removing it is a one-line change in each `AuthBrandPanel` / `AuthScaffold`.
- **`assets/logo.png` has an opaque light-blue background**, which is why the medallion is a circle
  crop with a white ring rather than a free-standing mark. If a transparent PNG or SVG of the mark
  ever exists, the panel can drop the ring and render the mark directly on the gradient — a change
  isolated to the two panel widgets.
